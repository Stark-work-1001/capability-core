# 02 · 规划文档

## 1. 产品定位

**能力核心（Capability Core）** 是一个 Windows 桌面应用形态的**跨智能体能力中枢**：

- **采集**：把本机所有智能体生态里的能力（技能 / MCP / 插件 / 提示词 / 智能体定义）统一扫描入库
- **中枢**：以 SQLite 为单一事实源，提供检索、详情、状态、健康、版本、来源
- **持有**：自己维护一份能力资产（`assets/`），可维修、可派发、可直接提供给接入的智能体
- **分发**：通过 MCP 协议让任何智能体主动检索与读取；通过生态同步把端点写进宿主配置
- **治理**：去重裁决、故障诊断、维修派单、更新巡检、生命周期与回收站
- **增强**：接入云端大模型做向量检索与精排，本地算法兜底

**明确不做**：不代替宿主执行技能；不自动改宿主代码；不做云同步与账号体系。

## 2. 能力的三分

这是本项目最核心的概念区分，决定了存储与职责边界：

| 概念 | 位置 | 含义 |
| --- | --- | --- |
| 能力资产库 | `assets/<kind>/<id>/` + `scope='own'` | 自己持有、可维修、可派发 |
| 宿主能力库 | 各宿主目录 + `scope='host'` | 扫描登记的外部能力索引 |
| 能力数据库 | `data/capability-core.db` | 两者的元数据、状态、维修记录与向量 |

**转化方向**：宿主能力 ──「转为能力资产」──▶ 能力资产库 ──「生态同步」──▶ 各智能体原生配置。

## 3. 技术选型与理由

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 桌面壳 | Electron 44 | 本机已有运行时缓存；主进程即后端，无需 sidecar；调试与截图验证成本低 |
| 界面 | React 19 + TypeScript + Vite 7 | 组件化、构建快 |
| 数据库 | SQLite（`node:sqlite` 内置） | 零编译依赖；FTS5 + trigram + JSON1 全部可用 |
| 后端 | Node 24 ESM | 与 Electron 同进程，IPC 直接调用，无跨进程序列化开销 |
| 对外协议 | MCP（stdio + Streamable HTTP） | 事实标准，主流智能体均支持 |
| 检索 | FTS5 BM25 + trigram + 向量 + 精排 | 云端增强、本地兜底，可解释、永不中断 |
| 模型 | 硅基流动（OpenAI 兼容） | embedding / rerank / judge / general 四角色解耦，可换任意兼容服务 |
| 打包 | 绿色目录（启动器 + Electron 运行时 + 应用 + 数据） | 开发自用阶段，不做安装包与签名 |

## 5. 职责边界

**中枢负责**：诊断、定位、汇报、派单、登记、检索、分发。

**中枢不负责**：猜怎么修、代替智能体执行、修改宿主源码。

维修流程：中枢诊断出故障 → 生成结构化工单 → 派给接入的智能体 →
智能体修复后通过 `capability.submit_patch` 回传 → 中枢校验路径边界后备份落盘。

## 6. 演进方向

- 多智能体协作维修（多个智能体同时接入、分工处理不同故障）
- 能力资产的可发布性（导出为标准格式供其他机器使用）
- 模型接入扩展到更多提供商与更多角色（如意图识别、能力推荐）
