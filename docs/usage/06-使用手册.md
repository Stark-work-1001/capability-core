# 06 · 使用手册

## 启动

两种方式，效果相同：

1. 双击 `release/启动-能力核心.cmd`
2. 直接双击 `release/runtime/CapabilityCore.exe`

`CapabilityCore.exe` 是原生启动器，它负责清除可能干扰 Electron 的环境变量并设置打包标记，
然后拉起 `CapabilityCore-GUI.exe`（Electron 本体）。**请始终用 `CapabilityCore.exe` 启动。**

首次启动会在后台扫描（约 20–30 秒），顶部「扫描全部」按钮显示扫描状态。
数据保存在 `release/capability-core-data/`，能力资产保存在 `release/assets/`。

> 首次运行若出现 Windows SmartScreen「未知发布者」提示，属绿色版未签名的正常现象，选择「仍要运行」即可。

## 界面地图

左侧分三组：

- **能力中枢**：总览 / 能力资产库 / 宿主能力库 / 检索实验室 / 智能体接入
- **治理**：来源与扫描 / 去重裁决 / 维修站 / 更新管理
- **运行**：工作流 / 模型接入 / 生态同步 / 数据库 / 设置

---

## 总览

四个指标卡（能力总数、在线智能体、待处理故障、重复/可更新）+ 能力构成 + 来源分布 + 最近事件 + 工作流状态 + 高频能力。

「⚡ 执行全量巡检」会依次跑：扫描 → 诊断 → 去重 → 重建索引 → 汇总。

---

## 能力资产库

这是能力核心**自己持有**的能力。与「宿主能力库」的区别见 README 的「能力的三分」。

- 顶部四张统计卡：资产总数 / 占用体积 / 分组类型 / 资产目录（可点开）
- 列表按类型分组（技能 / MCP / 插件 / 提示词）
- 点条目 → 右侧显示资产 ID、落盘路径与完整正文
- 操作：
  - **＋ 新建能力资产**：填类型、名称、正文，自动落盘到 `assets/<kind>/<id>/` 并登记数据库
  - **⇩ 从宿主能力转为能力资产**：从宿主能力库里挑一条，复制实体到资产库，保留来源追溯
  - **移入回收站**：物理目录移到 `assets/.trash`，数据库记录置为归档（可追溯，不真删）

> 同一宿主能力重复点击「转为能力资产」不会产生重复记录，会复用已有资产。
> 若源能力是「智能体」类型，转化时会降级为「技能」并在界面上明确标注（资产只有四种物理形态）。

## 宿主能力库

从各智能体安装目录扫描登记的能力索引。

- 顶部：名称/摘要/作者过滤、类型分段、状态下拉、导入按钮
- 左侧列表：类型图标、名称、版本、健康徽章、作者、状态、宿主、更新时间
- 右侧详情：概览（作者/版本/宿主/标签/主页/许可证/调用次数）、正文、安装（路径/指纹/大小）、故障
- 操作：启用/停用、校验完整性、创建快照、固定、删除、导出、打开安装位置

**导入能力**：点「＋ 导入能力」→ 选择目录 → 先「预检」看清单与问题 → 再「确认入库」。
入库会复制到 `assets/<kind>/<id>/`，原位置不变。

---

## 检索实验室

输入自然语言（中英均可），或点示例按钮。结果区可切换「结果 / JSON」。
每条结果下方显示匹配来源（名称/摘要/标签/子串/全文）。右侧面板展示同义词扩展词与打分构成。

启用了模型接入后，检索会先用向量召回、再用精排模型重排；
云端不可用时自动退回 FTS5 + trigram + BM25，界面上会标注本次是否走了本地兜底。

---

## 智能体接入

三通道识别的结果以卡片展示：运行中（进程识别）/ 心跳在线 / 未运行。

每张卡片右侧两个按钮：

- **⌁ 连通检测**（只读，不写文件）
  探测六项：`home`（宿主主目录）、`config`（配置可写性）、`process`（进程是否在跑）、
  `heartbeat`（心跳文件）、`session`（MCP 会话）、`endpoint`（端点可达性）。
  结果以 ✓/✕ 逐项展示，并给出总时延。
- **⇄ 主动连通**（会写文件，写前自动备份）
  把 MCP 配置写入该宿主的原生配置文件，返回写入的路径清单与备份号。
  写入后该智能体即可通过 MCP 获取能力核心的能力。

下方「MCP 接入配置」给出可直接复制的 JSON；「可写目标」列出能自动写入的宿主配置，
点「预览」看将写入什么，点「写入」执行。

右侧「最近 MCP 会话」显示真实连入的客户端、请求次数、工具调用分布。

## 模型接入

云端大模型接入，用于增强检索与判定。默认内置硅基流动。

**提供商**

- 列表显示名称、base_url、API Key（打码）、协议、最近检测状态
- 「测试连通」实测该提供商是否可用，返回时延与可用模型数
- 「添加提供商」可接入任意 OpenAI 兼容服务（自定义 base_url / key / 请求头）

**角色路由**

四个角色，各自绑定「提供商 + 型号」，随时可改：

| 角色 | 默认模型 | 说明 |
| --- | --- | --- |
| 向量嵌入 `embedding` | `Qwen/Qwen3-VL-Embedding-8B` | 向量检索，4096 维 |
| 精排 `rerank` | `Qwen/Qwen3-VL-Reranker-8B` | 提升命中顺序 |
| 判定 `judge` | `Qwen/Qwen3.8-27B` | 通用判定层 |
| 通用兜底 `general` | `Qwen/Qwen3.8-27B` | 其余场景默认 |

**调用统计**：累计调用数、按角色分布、最近调用明细（成功/失败、模型、时延）。

**本地兜底**：云端不可用时自动退回本地算法（哈希向量 + 词面精排 + 规则判定），
任何情况下检索与判定都不会中断。

> API Key 只保存在本地数据库，界面恒为打码显示，任何接口都不会回传完整密钥。

## 来源与扫描

按宿主分组列出全部来源：类型、根路径、上次扫描时间、状态、数量。
可以单来源扫描、停用、删除（内置来源不可删）。「＋ 添加来源」支持任意目录。

---

## 去重裁决

每组重复能力显示：相似度、实例数、判定原因、每个实例的版本/作者/路径/状态、推荐项（★）。

四个动作：

- **保留最新版本**（其余归档）
- **合并**（实例并入目标并保留全部标签/宿主）
- **允许共存**
- **忽略**

归档不删除磁盘文件。

---

## 维修站

- 顶部统计：未解决故障 / 可自动修复 / 已派单 / 维修记录
- 「执行诊断」跑全部规则
- 列表支持按状态与级别筛选
- 「自动修复」：仅对安全规则可用（补 frontmatter / 补 description），修复前自动备份
- 「派单」：选择智能体、写备注，生成结构化工单
- 点行打开详情：证据、维修历史（含修复前后哈希）

**工作方式**：中枢只诊断定位，修复由智能体执行；智能体修完通过 `capability.submit_patch`
回传完整文件内容，中枢校验路径边界后备份落盘。

---

## 更新管理

检查上游新版本，支持创建更新前快照。比对来源为本地缓存的上游目录，毫秒级完成。

---

## 工作流

可观察、可复跑的维护流程。内置「全量巡检」「能力入库」等流程，每一步的输入输出都会记录，
可查看历史运行与耗时。

---

## 生态同步

把中枢的能力推送到各智能体的原生配置。支持预览（看将写入什么）、写入（自动备份）、
从备份恢复。适用于「换智能体不用重配」的场景。

---

## 数据库

展示 SQLite 运行指标、各表行数、数据库文件大小与 WAL 状态，以及「能力三分」的归属统计。

---

## 设置

中枢行为开关（启动扫描、自动扫描间隔）、连接信息（MCP 端点、端口）、
以及本机路径（数据目录、资产目录）。
