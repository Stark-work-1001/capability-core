# 05 · 经验文档

> 只记录**踩过并已解决**的坑，以及同类项目可复用的判断。

## 一、SQLite / 检索

### 1. `node:sqlite` 的 FTS5 索引列不等于表列

建虚表时写了 `content='search_docs'`，外部内容表模式下虚表只暴露**索引列**（name/summary/body/keywords/author/hosts），
`capability_id` 这类非索引列必须 JOIN 主表拿：

```sql
SELECT d.capability_id, bm25(search_fts) AS score
FROM search_fts JOIN search_docs d ON d.rowid = search_fts.rowid
WHERE search_fts MATCH ? ORDER BY score
```

直接 `SELECT capability_id FROM search_fts` 会报 `no such column`。

### 2. unicode61 不切中文，trigram 也不切

实测：

| 方案 | 查询「能力中枢」 |
| --- | --- |
| 原样写入 + unicode61 | 空 |
| 原样写入 + trigram | 空 |
| CJK 逐字空格后 + unicode61 | 命中 |
| trigram 且查询为 ASCII | 命中 |

结论：**入库与查询两侧都做 CJK 逐字切分**，是零依赖下最稳的路径。
代价是「能力」和「力能」在索引层面等价，因此排序时用应用层字符对覆盖率补正。

### 3. `bm25()` 返回负值

FTS5 的 `bm25()` 越小越相关（负值）。直接当分数用会排反，取相反数即可。

### 4. SQL 占位符个数必须与列数、值数组三方一致

`INSERT INTO t(a,b,c) VALUES(?,?,?)` 里 **列数、`?` 个数、参数数组长度必须三者相等**。
多写一个 `?` 就会在运行时抛 `N values for M columns`，而 `tsc` 与 `typeof` 检查**都抓不到**。

这次踩到的实例：某处 INSERT 写了 25 列、26 个 `?`、25 个值，
导致新建能力的整条路径全废，只有真跑才会暴露。

**对策**：对全部 INSERT 做一次「列数 / 占位符数 / 值数组元素数」三方比对脚本，
顶层逗号计数、忽略嵌套括号与字符串内逗号。注意排除 FTS5 的
`INSERT INTO search_fts(...) VALUES('delete', old.rowid, ...)` 这类不含占位符的特殊语法。

### 5. 迁移必须幂等且能在真实老库上验证

`ALTER TABLE ADD COLUMN` 要先用 `PRAGMA table_info` 或等价手段检测列是否存在，
否则第二次启动就报错。验证时不要只测「新库能建表」，
要复制一份**真实老库**跑升级，确认数据条数不变、二次打开仍能成功。

## 二、Electron

### 6. `ELECTRON_RUN_AS_NODE` 只要存在就出事，不是「=1 才出事」

实测矩阵（同一份 electron 本体）：

| 取值 | 结果 |
| --- | --- |
| 未设置 | 正常出窗口 |
| `1` | 静默秒退 |
| `0` | 静默秒退 |
| 空串 `""` | 静默秒退 |

**关键认知**：模式判定发生在 Electron 原生层，`main.js` **根本没有执行机会**——
所以「在 JS 顶部检测并自我重启」这条路是走不通的。

也因此，`.cmd` 里写 `set ELECTRON_RUN_AS_NODE=`（置为空串）**同样无效**，
必须彻底 unset。最稳的做法是编译一个原生启动器，在任何 JS 执行前清掉环境变量。

### 7. preload 默认按 CJS 加载

把 preload 写成 `import { contextBridge } from 'electron'`（ESM），会静默失败：
页面加载了，但暴露对象是 undefined，界面一片空白。
即使 package.json 有 `"type": "module"`，preload 仍按 CommonJS 处理——**必须用 `require`**。

### 8. 打包态判定不能只依赖外部环境变量

最初用 `process.env.CC_PACKAGED === '1'` 判断是否打包，而这个变量**只有启动器会设**。
用户直接双击 exe（最自然的操作）时它不存在，于是落到开发态分支，数据被写进应用包内部——
备份会漏、升级会连数据一起覆盖。

**对策**：用多条互相独立的**物理证据**判定，任一命中即可：

1. 环境变量标记（最快路径）
2. `process.resourcesPath/app/package.json` 存在（打包布局的铁证）
3. Electron 原生 `app.isPackaged`

且 `paths.js` 要同时被 Electron 主进程和纯 node 的 CLI 引用，
所以不能直接 `import { app } from 'electron'`，要用延迟加载。

### 9. 截图验收比肉眼点更快

给主进程加一个 `CC_SHOT` 环境变量通道：启动后
`executeJavaScript('__ccGoto("view")')` + `capturePage()`，
一次启动就能拿到全部视图的真实渲染结果。配合 `CC_SHOT_WAIT` 等首扫完成，避免截到空库。

### 10. 「文件都存在」不等于「能启动」

只检查产物文件齐全是不够的。这次就遇到：所有文件都在、
`package.json` 的 main 也正确，但实际双击是静默秒退。

**唯一可靠的验收是真跑一次并读取启动日志**。

## 三、设计陷阱

### 11. 「已剥离 frontmatter 的正文」不能用来判断有没有 frontmatter

最初规则是 `!/^---\n/.test(inst.content)`。但 `inst.content` 存的是适配器解析后的**正文**，
frontmatter 早被剥离——于是 259 个正常技能全被判成「缺 frontmatter」。

正确做法：**在解析时记录事实**（`metadata.hasFrontmatter`），诊断只读事实。
这条经验可以推广：*不要让下游用不完整的数据反推上游状态*。

### 12. 安装路径是目录还是文件，必须显式解析

技能/插件的 `installations.path` 可能是目录，也可能是单个文件。
一律当目录处理会在 `statSync().isDirectory()` 处出错。
统一先 `split('#')[0]` 去掉 `#子路径` 后缀，再 `statSync` 判类型。

### 13. 同一实体要生成两次 id 时，先想清楚谁是主键

某处先 `newId()` 建目录、内部登记时又 `newId()` 入库，
导致**磁盘目录名 ≠ 数据库主键**，两者无法互相反查。

**对策**：id 只在最外层生成一次，向下传参；内部函数接受可选 `input.id`。

### 14. 「转换」类操作必须显式报告降级，不能静默伪装

把 `kind='agent'` 的宿主能力转成能力资产时，资产只有四种物理形态，
只能落成 `skill`。如果静默转换，用户会以为资产还是智能体类型。

**对策**：返回 `kindCoerced / fromKind / toKind / note`，界面上明确标注。

### 15. 幂等写入要按语义查重，不能只靠主键

同一宿主能力重复「转为能力资产」，如果不查重就会产生多条独立记录，
用户重复点击几次资产库就翻倍。

**对策**：写前按业务标识（如 `metadata.promotedFrom`）查已有记录，
命中则复用或按参数覆盖。

## 四、协作经验

### 16. 不要在别人还在写文件时取样

子任务并行修改同一仓时，中途取证会读到编辑中的中间态，
把「语法错误/暂时未定义」误判成真实缺陷。

**对策**：验收一律等对方明确声明「交付完成」之后再做；
中途只做只读勘察，不做判定。

### 17. 子智能体上报的缺陷要自己复核，反之亦然

这次双向都发生过：

- 工程层上报「SQL 占位符多一个」——我重新数了一遍，确认为真；
- 我上报「打包后数据写进应用包」——工程层复核后确认；
- 但我也曾把「编辑中间态」误判成缺陷——自己复核时否掉了。

**对策**：任何缺陷在退回去修之前，先自己独立复现一次；
复现不了就不退回，先查取样条件。
