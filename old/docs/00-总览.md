---

## 1. 这是什么

CapabilityCore 是一个**桌面端智能体能力中枢**。它解决一个具体问题：

> 智能体需要某个能力时，不必去折腾安装插件，而是到中枢里**检索并直接调用**。

它同时托管六类资产：**Skill / MCP / Plugin / Suite / Ghost / Organization**，
并对外暴露 MCP 接口，让多个智能体接入协同。

## 2. 六层架构（修正版）

```
┌──────────────────────────────────────────────────────────────────┐
│ L6  套件 / 工作台          Suite & Workbench          ▲ 我们定义 │
│     把 L1-L5 组装成开箱即用的一栈                                │
├──────────────────────────────────────────────────────────────────┤
│ L5  组织（智能体编队）    Organization & Delegation    ▲ 我们定义 │
│     领导智能体 → 子智能体的派发关系；能力沿链逐跳收窄            │
│     ⚠ 这层全网无现成方案，是本项目最独特的资产                    │
├──────────────────────────────────────────────────────────────────┤
│ L4  身份（执行过程身份）  Capability Identity          ▲ 我们定义 │
│     智能体运行时的多维度身份：authority / side_effect /          │
│     tool_posture / idempotent / open_world / 自定义维度          │
│     ⚠ 注意：不是用户身份，不是 OAuth 主体                         │
├──────────────────────────────────────────────────────────────────┤
│ L3  检索与路由            Retrieval & Routing          ▲ 核心     │
│     四级瀑布：①Rust 全文内核 ②向量语义 ③融合排序 ④LLM 判定      │
│     向量层宕机时自动降级到 ①，永不失败                           │
├──────────────────────────────────────────────────────────────────┤
│ L2  资产注册与分发        Registry & Packaging          ▲ 核心     │
│     覆盖 MCP / Skills / Plugin 三类异构格式，统一成 Capability    │
│     Manifest；Plugin 层无跨厂商标准，是唯一可定标准的位置         │
├──────────────────────────────────────────────────────────────────┤
│ L1  连接与执行            MCP Protocol                  ○ 完全适配 │
│     别人的标准，不重造                                           │
└──────────────────────────────────────────────────────────────────┘
```

## 3. 关键技术选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| 内核语言 | **Rust 1.99.1** | 用户指定；稳定性与性能 |
| 桌面壳 | **Tauri 2** | 安装包 5-10MB，Rust 内核可被前端直接调用，无需 sidecar |
| 全文检索内核 | tantivy / quickwit | 兜底层必须**永远可用**，零外部依赖 |
| 向量层 | all-MiniLM-L6-v2（已有） | 离线、免费、384 维 |
| 存储 | SQLite | 单文件、零运维 |
| 外部协议 | MCP + A2A | 标准，不造 |

## 5. 模块耦合关系

**全部解耦。** 具体边界：

```
ac-core  （协议层，零 IO、零依赖）
   ▲  ▲  ▲  ▲  ▲
   │  │  │  │  └── ac-ipc      只做类型转换
   │  │  │  └──── ac-mcp       通过 trait 消费检索能力
   │  │  └─────── ac-llm       不依赖任何其他 crate
   │  └────────── ac-retrieval  通过 trait 抽象存储后端
   └───────────── ac-registry   存储实现
```

**关键约束（写在架构纪律里）**：

1. `ac-core` 不依赖任何 crate，不做任何 IO
2. `ac-retrieval` **不直接依赖 ac-registry** —— 二者通过 trait 通信，
   这样检索算法可以脱离 SQLite 单独测试，也能换成别的存储后端
3. `ac-llm` 是叶子节点，谁都不依赖它
4. crate 之间禁止循环依赖
