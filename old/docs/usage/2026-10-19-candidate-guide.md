# 候选版使用与审核

双击候选目录中的 `assets-desktop.exe`。首次启动会校验并部署随包 WebView2；离线可用，Windows 自带 PowerShell 用于部署。界面标题应为“待审核候选版”，端口为 18297。数据库在候选目录的 `data/registry.db`。开发版使用 18197，日常 standalone 使用 18198。

建议依次检查：在线智能体的进程证据与主动连接是否区分；五种检索方式；新增能力预览和发布；模型分工的十六项工作流；故障清单和维修记录；去重比较与合并草稿。

## 模型

“模型配置”提供十个卡片。前三个槽位预填模型和 SiliconFlow 地址，默认禁用、不带密钥；其余模型名留空。

向量模型只负责嵌入。诊断、修复、去重、生产使用通用生成模型；可以为专项槽位分别配置模型，也可以通过通用判定槽位回退。备用槽位用于服务失败降级。验收模型若与生成模型相同，工作流会保留该事实，不将其冒充为不同模型的独立复核。

填入自己的密钥、启用后先点击“测试连接”，再执行工作流。当前交付未包含真实云端效果验收。

## 智能体接入

支持 MCP Streamable HTTP 的客户端可连接 `http://127.0.0.1:18297/mcp`。客户端先 initialize 建立会话，之后由会话身份登记连接与用量。进程存在本身不等于已连接。

支持 stdio 的客户端可使用以下配置，并将路径替换为候选目录实际位置：

```json
{
  "mcpServers": {
    "capability-core": {
      "command": "C:/work/capability-core/artifacts/candidates/20261019-090352/assets-serve.exe",
      "args": ["mcp", "--db", "C:/work/capability-core/artifacts/candidates/20261019-090352/data/registry.db"]
    }
  }
}
```

不同客户端的 HTTP 配置结构可能不同；协议支持矩阵说明实际覆盖范围。外部工具用于检索、读取能力内容和协作登记，实际执行技能/MCP 工具仍由宿主负责。

## 发布和维修

新增能力先填写入口正文与来源，再生成预览，核对文件、摘要及警示后发布。版本写入纳管目录，原始 vendor 保留。MCP 发布后自动执行配置与依赖巡检；静态巡检通过之后仍需在真实宿主调用验收。

修复工作流生成入口修订草稿，经模型和规则校验后等待审核发布。维修历史保存方案、尝试和边界；无法修复的事项保持明确记录。多文件修复可使用后端 `prepare` / `commit` 命令提交完整文本包。

技能合并生成新草稿并保留原资产，自动生成结果不能覆盖无关的既有纳管资产。旧版纳管内容可通过“版本回滚”选择历史摘要恢复；内容被修改的历史版本会拒绝回滚。

## 审核后更新日常版

审核通过后再使用 `scripts/promote-candidate.ps1`。它保留旧程序文件，不复制开发/候选数据库，不覆盖日常版已有模型凭据。尚未收到审核指令时，不更新日常使用目录。
